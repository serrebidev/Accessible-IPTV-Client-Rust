# 0054 — Safe interoperable settings imports (issue #133)

Fresh verification on this revision, kept distinct from the
historical slice-#99 evidence. The format is Python's
`settings_backup.py`: Fernet (AES-128-CBC + HMAC-SHA256) over the
config JSON, key from PBKDF2-HMAC-SHA256 at 600,000 iterations,
envelope `accessible-iptv-settings-v1` — the Rust core mirrors it
byte-for-byte with Python's error strings.

## Desktop workflow (code-verified)

Options → Import Settings: file choice, one masked password
entry, decrypt, JSON-object validation, then an explicit
Replace confirmation (Yes/No) — the config file is written only
after every step succeeds, so a wrong password, a malformed
envelope, invalid settings, or a cancellation at any prompt
leaves current settings untouched. Import never restarts the app;
the status line says "Settings imported. Restart the app to use
them." and the restart stays the user's choice. Export uses a
masked entry plus a masked confirmation entry with Python's
"A backup password is required." / mismatch dialogs. Errors land
on the status line (the screen-reader live region).
