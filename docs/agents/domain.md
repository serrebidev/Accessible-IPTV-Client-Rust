# Domain Docs

This is a single-context repository.

## Before exploring

- Read `GLOSSARY.md` at the repository root when it exists.
- Read ADRs under `docs/adr/` that touch the area being changed.
- If these files do not exist, proceed silently; create them only when domain modeling or an architectural decision requires them.

## Vocabulary

Use the glossary's defined terms in issue titles, proposals, refactor descriptions, and test names. If a needed term is absent, treat that as a domain-modeling gap rather than silently inventing competing terminology.

## ADR conflicts

If proposed work contradicts an existing ADR, call out the conflict explicitly instead of silently overriding it.
